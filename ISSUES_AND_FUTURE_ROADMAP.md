# MSDL-JCI: Expert Machine Learning Engineering Issues & Future Roadmap

This document outlines structural, algorithmic, and engineering improvements identified during the architectural audit and empirical evaluation of the **MSDL-JCI** system. These issues can be directly created in the GitHub issue tracker or implemented in subsequent development cycles.

---

## 📌 Issue #1: Dynamic Decision Boundary Calibration & Class-Imbalance Focal Loss
- **Type:** `Algorithm / Model Performance`
- **Priority:** `High`
- **Labels:** `enhancement`, `ml-modeling`, `thesis-defense`

### Description
In financial directional forecasting over short-to-medium horizons ($t+5$), empirical evaluation on JCI historical data (2018–2025) reveals a natural upward drift (~54.5% UP vs ~45.5% DOWN). While the model achieves an **Accuracy of 57.56%** and **F1-Score of 72.97%**, the static 0.5 decision threshold causes high recall (99.5%) and lower specificity on DOWN regimes.

### Proposed Technical Solution
1. **Focal Loss Integration**: Replace standard `BCEWithLogitsLoss` with a Focal Loss objective:
   $$\mathcal{L}_{focal} = -\alpha_t (1 - p_t)^\gamma \log(p_t)$$
   to penalize easy negative examples and force the network to learn subtle transition signals.
2. **Youden's J Threshold Calibration**: Optimize the decision threshold $th^*$ on the validation fold by maximizing:
   $$J(th) = \text{Sensitivity}(th) + \text{Specificity}(th) - 1$$
   rather than assuming a default $0.5$ cutoff.

## 📌 Issue #2: Interactive Regime Shift & Dynamic Soft Gating Visualization Dashboard
- **Type:** `Visualization / UX / Thesis Presentation`
- **Priority:** `High`
- **Labels:** `ui`, `visualization`, `interpretability`

### Description
A core theoretical contribution of the thesis is the **Adaptive Soft Gating Network**, which dynamically outputs weighting coefficients $(\alpha, \beta, \gamma)$ for Technical, Macroeconomic, and News modalities. While these are exported to `data/processed/gating_weights_trajectory.csv`, presenting static CSV files during the thesis defense underutilizes the model's explainability.

### Proposed Technical Solution
1. Develop a lightweight **Streamlit / Dash web application** in `src/msdl_jci/app/`:
   - Dual-axis time series plotting JCI historical price against dynamic weights $(\alpha, \beta, \gamma)$.
   - Interactive inspection of critical market shocks (e.g., COVID-19 crash in March 2020, BI-Rate hiking cycle in 2022).
   - Display corresponding financial news headlines that triggered shifts in $\gamma$ (news attention).

## 📌 Issue #3: Automated Bayesian Hyperparameter Optimization (Optuna Integration)
- **Type:** `Engineering / MLOps`
- **Priority:** `Medium`
- **Labels:** `optimization`, `experimentation`

### Description
Currently, hyperparameters such as the lookback window (28), LSTM layers (2), dropout rate (0.2), and projection layer dimensions (64) are fixed according to literature specifications. A systematic Bayesian search can identify optimal configurations for different prediction horizons ($t+1, t+5, t+10$).

### Proposed Technical Solution
1. Add an Optuna study pipeline in `src/msdl_jci/experiments/optimize_hyperparameters.py`.
2. Implement pruning and objective maximization based on validation Sharpe Ratio and F1-Score.
3. Ensure walk-forward expanding window boundaries are strictly maintained during optimization to prevent cross-fold data leakage.

## 📌 Issue #4: Real-Time Daily Ingestion & Automated Inference Runner
- **Type:** `MLOps / Productionization`
- **Priority:** `Medium`
- **Labels:** `production`, `cli`, `automation`

### Description
Currently, the pipeline runs in offline batch mode on historical datasets. To support continuous evaluation on live market data, the system needs an automated daily ingestion script that fetches daily OHLCV from Yahoo Finance, scrapes the latest financial news, queries macroeconomic indicators, and outputs an actionable prediction signal for the next 5 days.

### Proposed Technical Solution
1. Create `src/msdl_jci/inference/daily_predict.py`:
   - Automatically pull latest day $t$ OHLCV via `yfinance`.
   - Run crawler for Detik/Kontan/CNBC articles published on date $t$.
   - Load pre-trained checkpoint `best_proposed_model.pt`.
   - Emit daily trade recommendation: `BUY / LONG` or `HOLD / CASH`.

## 📌 Issue #5: Explicit Financial Sentiment Polarity Scoring for IndoBERT Embeddings
- **Type:** `NLP / Feature Engineering`
- **Priority:** `Medium`
- **Labels:** `nlp`, `indobert`, `feature-engineering`

### Description
The news branch uses general semantic representations from Frozen IndoBERT via attention mean-pooling. While this captures general topic semantics (e.g., interest rate policies, banking earnings), high-frequency sentiment polarity (extremely bullish vs. panic selling) can be diluted.

### Proposed Technical Solution
1. Concatenate an explicit 1D sentiment polarity score $s_t \in [-1, 1]$ generated by an Indonesian financial sentiment classifier to the 64-dim projected news representation.
2. Evaluate whether explicit sentiment features improve direction prediction accuracy during panic sell-off events.
